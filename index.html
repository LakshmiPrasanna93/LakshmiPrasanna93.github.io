AI agentEvals0 → GA

Taking an enterprise AI assistant to GA, gated by evals

Role: PM owner, from scoping through launch.

Problem

Admins spent too long hunting for answers across complex admin screens. "It looked good in the demo" wasn't a launch bar we could defend to enterprise customers.

What I did

  • Scoped v1 as a read-only Q&A agent, with access scoped by each user's role
  • Designed a 200+ case eval suite with P0 gates: tool selection ≥95%, parameter accuracy ≥90%, response quality ≥4/5, guardrails 100%
  • Tracked known bugs separately, so an eval regression always meant a new failure

Key trade-off

Evaluated a multi-agent supervisor architecture and deferred it because of latency. Single-agent first, with complexity added only when the data asks for it.

Result: GA across 60 eligible top-tier accounts, with an objective go/no-go bar and a regression net for every prompt change. Now building v2: a multi-agent system where admins confirm every change before it runs, with a full audit trail and 24-hour rollback.

LLM costPrompt design

Cutting agent token cost 40–45% without losing quality

Role: hands-on owner of the agent instruction files.

Problem

Multi-agent instruction files had grown long and full of "never do X" lists. Every call paid for that bloat in latency and spend.

What I did

  • Rewrote each sub-agent with numbered rule IDs
  • Replaced prohibition lists with gold examples
  • Designed handoffs between agents that carry IDs, so context isn't re-sent

How I knew it worked

Re-ran the same eval gates after the rewrite, so the token cut didn't cost quality.

Result: about 40–45% fewer input tokens per sub-agent in the v2 multi-agent system, with eval scores held.

PlatformComplianceDiscovery

Audit logs, from zero to GA

Role: PM owner across discovery, PRDs and phased delivery.

Problem

Customers couldn't answer "who changed what, and when?" Any history that existed was spread across legacy modules.

What I did

  • Ran discovery on retention needs, usage patterns and pricing sentiment
  • Wrote PRDs for field-level diffs, bulk-update grouping, tiered retention (soft and hard archive) and tombstones for deleted entities
  • Wrote the cost and pricing drivers

Why it mattered

An audit trail is the precondition for letting an AI agent make changes. It made the AI v2 roadmap possible.

Result: PRD to GA in 6 months, giving customers change history for users, vehicles and devices. Legacy unification is planned next.

How I work

  1. Evals before launch dates

    A model is ready when it passes the gates, not when the sprint ends.

  2. Ship the boring version first

    Single-agent, read-only, scoped by role. Then expand.

  3. Tokens are a product cost

    Latency and spend are UX. I treat prompt size the way I'd treat page weight.

  4. Trust is a feature

    Audit trails and permissions are what make an AI agent safe enough to act.
